# 数据撰写规范（「同代」项目）

目标：为每位作家列出 10–16 位**同时代**著名人物，并写清两人**何时相识、交往中发生了什么大事**，包括**绝交/反目**这类关系终结。

## 一、文件格式

每个 `data/*.js` 文件是一个自包含分片，必须严格保持这个外壳：

```js
window.AUTHORS = (window.AUTHORS || []).concat([
{
  id: "libai",
  name: "李白",
  en: "Li Bai",
  alias: ["李太白", "青莲居士"],
  birth: 701,
  death: 762,
  country: "中国 · 唐",
  era: "盛唐",
  field: "诗歌",
  bio: "……（60–120 字，写TA在文学史上的位置与最特别之处，要有观点，不要百科腔）",
  works: ["将进酒", "蜀道难", "静夜思"],
  peers: [
    {
      n: "杜甫",
      e: "Du Fu",
      b: 712,
      d: 770,
      c: "中国 · 唐",
      f: "诗歌",
      t: "friend",
      r: "挚友：一生念念不忘",
      met: 744,
      metAt: "洛阳",
      ev: [
        { y: 744, e: "洛阳初遇，同游梁宋，与高适三人同行，访道寻仙" },
        { y: 745, e: "石门分别，李白南下江东，杜甫西去长安" },
        { y: 746, e: "杜甫客居长安，写下《春日忆李白》" }
      ],
      x: "……（60–160 字的总述，写这段关系为什么重要、留下了什么）"
    }
  ]
}
]);
```

**注意**：文件必须以 `window.AUTHORS = (window.AUTHORS || []).concat([` 开头、以 `]);` 结尾；对象之间用逗号；字符串用双引号；不要写 `//` 注释。

## 二、字段说明

### 作家（author）

| 字段 | 类型 | 说明 |
|---|---|---|
| id | string | 全库唯一，小写英文/拼音，如 `libai`、`shakespeare` |
| name | string | 中文常用名 |
| en | string | 英文名或罗马字，可省略 |
| alias | string[] | 笔名、字号、别译，便于搜索，1–4 个 |
| birth | number | 生年，公元前用负数（前 278 → `-278`） |
| death | number \| null | 卒年；仍在世用 `null` |
| country | string | `中国 · 唐` / `英国` / `俄国` 这种格式，中国一律以「中国」开头 |
| era | string | 时代或流派，如 `盛唐`、`维多利亚时代`、`现代主义` |
| field | string | 主要身份，如 `诗歌`、`小说`、`戏剧`、`哲学`、`散文` |
| bio | string | 60–120 字，有观点 |
| works | string[] | 3–5 部代表作 |
| peers | array | 10–16 位同时代人物 |

### 同代人物（peer）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| n | string | 是 | 姓名。若此人也是本库作家，**必须与作家名单里的写法完全一致** |
| e | string | 否 | 英文名 |
| b | number | 是 | 生年 |
| d | number \| null | 是 | 卒年 |
| c | string | 是 | 地域，同 country 格式 |
| f | string | 是 | 领域：`诗歌`/`小说`/`哲学`/`科学`/`绘画`/`音乐`/`君主`/`政治`/`戏剧`/`建筑`… |
| t | string | 是 | 关系类型，见下表 |
| r | string | 是 | 关系短语，6–18 字，一句定性，如「忘年知己」「论敌：一生的对手」 |
| met | number \| null | 是（t≠none） | **相识年份**。确实无考写 `null`，并在 metAt 写「具体年月失载」 |
| metAt | string | 否 | 相识地点或契机，如 `长安`、`经人介绍`、`在伦敦的宴会上` |
| ev | array | 是（t≠none） | **交往年表**，1–4 条，见下 |
| end | number \| null | 否 | 关系终结年份（绝交、反目、一方去世、失联） |
| endWhy | string | 否 | 终结方式，如「绝交：因《项狄传》之争反目」 |
| x | string | 是 | 60–160 字总述 |

`ev` 数组每一项：`{ y: 年份或 null, e: "发生了什么" }`。`e` 写 15–40 字，写具体的事：写了哪首诗、哪封信、哪次争吵、谁引荐了谁。

### 关系类型 `t`

| 值 | 含义 | 典型例子 |
|---|---|---|
| `friend` | 友人、挚友、知己 | 李白与杜甫 |
| `rival` | 论敌、政敌、文学对手 | 伏尔泰与卢梭 |
| `mentor` | 师承、提携、后学 | 苏轼与黄庭坚 |
| `family` | 亲属 | 苏轼与苏辙 |
| `circle` | 同圈、同社、同流派 | 伍尔夫与布卢姆茨伯里圈 |
| `patron` | 知遇、君臣、赞助人 | 屈原与楚怀王 |
| `context` | 同处一个局势但无深交 | 同时代的政治人物 |
| `influence` | 隔代或单向影响（生命必须仍有重叠，只是未曾交往） | 歌德之于青年卡莱尔 |
| `none` | **同代但确无交集** | 同岁、同城、同以诗名，却无一首唱和 |

## 三、硬性要求

1. **每人 10–16 位** peers，其中**至少 2 位** `t: "none"`（同代但无交集），这是本站的特色，必须写清「他们各自在做什么」。
2. `t !== "none"` 的每一条**必须**有 `met`（或 null）和**至少 1 条** `ev`。
3. 生命期必须与作家本人**有重叠**（同代）。跨时代的影响关系（如但丁之于维吉尔）只在确有文学史意义时用 `t: "influence"`，且最多 1 条。
4. **绝交、反目、决裂要写**：有明确终结的，加 `end` + `endWhy`，并在 `ev` 里补上导致决裂的事件。这是本次改版的重点。
5. **准确优先**：年份、书名、地名只写有把握的。记不清具体年份就写 `met: null` 或 `y: null`，并在文字里写「约」「具体年月失载」。**绝不允许编造看起来精确的假年份。**
6. `x` 和 `ev[].e` 里不要重复同一句话；`x` 写总述与评价，`ev` 写事件。
7. 地域跨度要大：每位作家至少 1–2 位**其他文明**的同时代人（如李白页面上出现阿拉伯的阿拔斯王朝、欧洲的查理曼），标注 `t: "none"` 或 `context`，用来做跨文化对照。
8. 语言：简体中文，克制、具体、有文学感。避免「被誉为」「极大地」这类空话堆砌。

## 五、校验

```bash
cd <项目根目录>
node --check data/你的文件.js
node .dev/validate.js
```

`validate.js` 会报出缺字段、类型错误、none 类型却写了年表等问题。**必须做到 0 error 再交付。**
